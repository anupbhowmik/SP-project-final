# Project Overview
This project simulates the memory usage of different Key-Value (KV) cache backends for large language model (LLM) inference. It focuses on how prompt prefix sharing can reduce memory waste. The simulation is multi-threaded and models how LLMs store and reuse token activations during sequence decoding.

## Anup Bhowmik
========== Simulation Setup ==========
Implemented a simple multi-threaded simulation for sequence decoding using a KV backend.
This simulator models the memory usage of LLM (Large Language Model) KV (Key-Value) caches during concurrent decoding.

------------------ Features ------------------
KV Cache: 
In transformer models, each token processed generates key and value vectors that are stored in a cache for use in future attention computations.

Multi-threaded Simulation:
Each sequence is processed in a separate thread using POSIX threads (pthread). Threads simulate prompt token generation.

Token Generation Simulation:
For each sequence, tokens are appended to the backend for both prompt and generation phases. Sleep (usleep) simulates processing time per token.
Other steps (like attention, feedforward, attention, softmax, or neural network layers, etc.) are not simulated because They do not affect the memory layout of the KV cache.
The simulator's goal is to measure peak memory usage for the cache, not to simulate the full computation of the model.

Thread Arguments Struct:
ThreadArgs struct passes necessary data (backend, config, work, index) to each thread.

Backend Interaction:
Uses functions from kv_backend.h to initialize sequences, append tokens, and collect statistics.

Resource Management:
Dynamically allocates and frees memory for thread handles and arguments.

Statistics Collection:
Returns backend statistics after all threads complete.


========== Main Setup ==========
contains the entry point and main simulation driver for the project. It sets up the simulation configuration, generates a workload with shared prefixes, runs two different KV backends (monolithic and paged with prefix sharing), and prints memory usage statistics for each backend.

Steps:
1. Setup mono KV backend and page KV backend and their configuration
2. Initialize random seed
3. Generate a workload array of SequenceWork structs, ensuring that sequences are grouped for shared prefix simulation. Each group here share the same prompt prefix
4. Run simulation (both mono and paged)
5. Print stats and results
6. Free workload and other allocations
